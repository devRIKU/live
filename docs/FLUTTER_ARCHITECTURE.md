# Lively OpenAll — Flutter Rewrite Architecture

## 1. Goal
Replace the Tauri/React/Vite stack with a native Flutter (Windows) app using Impeller GPU rendering, Fluent/WinUI aesthetics via `fluent_ui`, and Riverpod state management. No webview, no Rust backend.

## 2. Project layout
```
flutter/                       # new Flutter app root (repo stays clean)
  pubspec.yaml
  lib/
    main.dart                  # window bootstrap + ProviderScope
    app.dart                   # FluentApp.router
    core/
      theme/                   # FluentThemeData from design tokens
      router/                  # go_router
      state/                   # Riverpod controllers
      services/                # HTTP/SSE, storage, providers, MCP, voice
      models/                  # immutable data classes (json_serializable)
      native/                  # FFI + platform channels
    features/
      shell/                   # NavigationView, sidebar, composer
      chat/                    # turns, streaming, attachments
      genui/                   # OpenUI Lang renderer (port of src/genui)
      surfaces/                # artifact pane, research, connectors, terminal, voice, overlays
      settings/                # settings dialog
    shared/
      widgets/                 # reusable Fluent widgets
      icons/                   # icon set
  windows/                     # native Windows runner (generated by flutter create)
  assets/
  test/
scripts/
  setup-flutter-cache.ps1      # routes PUB_CACHE / build cache to E:
```

## 3. Web -> Flutter module mapping
| Web module (src/) | Flutter module |
|---|---|
| app/App.tsx, shell/* | features/shell |
| chat/*, providers, sse, transport | core/services/chat + features/chat |
| genui/* (schema, library, components, prompt, split, validate, OpenUIMessage, actions) | features/genui |
| surfaces/* | features/surfaces |
| app/SettingsDialog | features/settings |
| adapters/* (desktop, mcp, localMcp, proxy, research, voice, webConnectors, codeAgent, skills) | core/services/* |
| db/* (sqlite/indexedDb adapters, storageAdapter, exportImport) | core/services/storage (sqflite_common_ffi) |
| canvas/artifactDetector | features/surfaces/artifact_pane |
| tools/* | core/services/tools |
| styles/tokens.css, motion.css | core/theme (FluentThemeData + animation constants) |

## 4. State management
Riverpod. Providers mirror web hooks:
- `themeControllerProvider` (ThemeMode)
- `chatControllerProvider` (thread list, active thread, streaming)
- `settingsProvider`
- `providersProvider` (LLM provider config)
- `mcpProvider`, `connectorsProvider`, `researchProvider`, `voiceProvider`

## 5. Native system hooks
- Window chrome: `window_manager` (frameless, hidden title bar).
- SQLite: `sqflite_common_ffi` with desktop init.
- FFI: native tool hooks (file system, process) via `dart:ffi` calling a small C shim; or method channels to a Windows plugin. Heavy hooks (terminal) use `xterm` + `dart:io Process`.
- Secure storage for API keys: `flutter_secure_storage` (Windows Credential Manager).

## 6. Performance
- Impeller (default on Windows in recent Flutter). Enable with `--enable-impeller` if needed.
- Avoid webview; all rendering native.
- Streaming chat uses SSE via `http`/`dio` parsed on isolate for large payloads.

```
# Flutter build cache (engine artifacts) defaults under FLUTTER_ROOT; point tool state:

```

## 9. Current port status (Oct 2026)
- Chat core complete: `core/services/chat/` (tokens, failover, SSE, transport, attachments, model_params, controller, thread_controller) + `features/shell` (sidebar, model bar, composer, message turns, 3-col shell).
- OpenUI Lang renderer complete: `features/genui` (schema, parser, split, validate, nodes, actions, runtime, all component widgets including `Form`, and the `OpenUIMessage` renderer) wired into `MessageTurn` and `ShellScreen._handleAction`.
- Tool approval flow ported: native tools (`core/services/tools/native_tools.dart`), text-protocol detector (`tool_call_detector.dart`), `PermissionCard` surface, queue/decide/execute loop in `shell_screen.dart` (memory:save, research:start, mcp:*, web connectors), artifact detection + `ArtifactPane` side panel with **WebView2** rendering for HTML/SVG artifacts.
- Settings: `features/settings/settings_dialog.dart` against `settings_controller.dart` (params, facts, secrets, export/import).
- Storage: `storage_adapters.dart` barrel (memory + sqlite + export/import); `SqliteStorageAdapter.open()` wired in `main.dart` on E:-friendly cache layout.
- App shell wraps `FluentApp.router` in a material `Theme` mirroring Fluent brightness so genui/markdown/material widgets resolve Lively tokens without crashing.
- Skills bundled from `assets/skills/*/SKILL.md` and folded into the system prompt; durable facts likewise.
- Milestone surfaces ported and wired into `ShellScreen` (all written without a Flutter SDK — **never compiled or run**; expect a first `flutter analyze` pass to turn up fixes):
  - `ResearchOverlay` — opened by the Deep-research chip or the `research:start` tool; polls the research adapter every 2 s (demo/mock when no service URL is configured).
  - `VoiceDock` + `_toggleVoice` — drives `VoiceProvider`. The native speech plugin (method/event channels in `voice_adapter.dart`) is **not implemented**. On Windows `VoicePlatform.nativeVoiceAvailable` defaults to true, so `NativeVoiceProvider` is chosen and starting to listen hits `MissingPluginException`, which the shell turns into a "not installed in this build" toast. No dictation works until that plugin exists (or `setVoiceProvider(MockVoiceProvider())` is called for demos).
  - `AccountPanel` — opened from the sidebar account menu ("Profile & plan"). Plan/sign-out are placeholders, as in the TS build.
  - `ConnectorsOverlay` — add/test/toggle/remove web connectors; reached via Tools → "Web connectors".
  - `CustomizeOverlay` — personality + custom instructions persisted under `lively.customInstructions`; opened from Settings. As in the TS build, the saved instructions are **not yet folded into the system prompt**.
  - `ModelOverlay` — reads live providers from `backendProvidersProvider`; drops image attachments when switching to a text-only model. Per-model sampling params are **not** swapped on model change.
  - `TerminalDock` — real `xterm` emulator over the code-agent provider (native `Process` with plain pipes; interactive TUIs such as `opencode` need a ConPTY launcher, see `CodeAgentLauncher`).
  - `ToolsOverlay` — tool switches, connectors and terminal entry points.
- MCP: tools from **connected remote** MCP servers (`tools/list`, refreshed at shell start) and enabled web connectors are offered to tool-capable models. Local stdio servers are spawned per call and can't be listed without spawning, so they are not advertised. Nothing in the UI connects an MCP server yet, so in practice only web connectors contribute today.
- Artifact preview: HTML/SVG render in WebView2 via **`webview_windows`** (`webview_flutter` has no Windows support). Requires the WebView2 runtime and, to build the plugin, Visual Studio + nuget. A strict CSP is *always* injected (even when the artifact ships its own) so a permissive model-written policy cannot loosen the sandbox. Markdown uses the native viewer; React artifacts show source only.

## 10. Things that don't work yet
- **Voice dictation:** now uses the `speech_to_text` plugin (Windows UWP speech recognition, beta upstream). The OS ends a session after a pause, and Windows needs "Online speech recognition" enabled in Settings → Privacy → Speech. Dictation works in demo mode via `MockVoiceProvider` (never selected by default — install with `setVoiceProvider`).
- **Custom instructions:** now folded into the system prompt (personality, about, respond). Ported from the TS `CustomizeOverlay`.
- **Model switching:** now calls `selectModel` which loads the model's saved params (or defaults), clamped to what the model supports.
- **MCP connectivity:** connectors panel now connects/disconnects MCP servers via `mcpClient.connect`/`disconnect` on toggle/add/remove. Tool list is refreshed at shell start and on connector changes.
- **Terminal interactivity:** now uses `flutter_pty` (ConPTY on Windows) for interactive TUIs. Needs the `flutter_pty` FFI plugin to build (Visual Studio + CMake).
- **Artifact preview:** requires WebView2 runtime + Visual Studio/nuget to build. Strict CSP always injected.
- **Research:** falls back to `MockResearchProvider` when no service URL is configured.
- **Account panel:** plan/sign-out are placeholders (matches TS build).
- **Credential vault:** now backed by `flutter_secure_storage` (OS-protected). Keys saved in Settings take priority over environment variables.
- **Image generation:** the `image` chip switches to `gemini-3.1-flash-lite-image`; image requests route through the backend's `/api/images/generations` endpoint. Inline data URIs are rendered by `MarkdownView` (SVG shown as alt text).
- **No testing has been done:** no Flutter SDK in this environment; expect first `flutter analyze`/`build` to surface more issues.

## 11. Notes
Flutter SDK is not present in this environment; the scaffold is created for completion on a machine with Flutter installed. Run `flutter create --platforms=windows .` inside `flutter/` to generate the `windows/` runner if missing, then `flutter pub get`.
